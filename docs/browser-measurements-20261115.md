# 瀏覽器實測與人工驗收 — 2026-11-15

本輪修改只在 standalone Super Chart 工作目錄，沒有推送、發布或觸發 CI。比較版本：
- 舊版：已發布的 `@super-solution/super-chart@0.0.53` + KLineCharts 9.8.12。
- 自研改前：固定 Git `5b9b7d0b329cd0853735f2eaeb75c70e31baf7f9`。
- 自研改後：本輪工作目錄，包含閒置 drawing Canvas 釋放。

## 方法與可解讀範圍

ChatGPT in-app Chromium，Windows，同一個 top-level 分頁，每組重新載入；1074×884 CSS px、DPR 1。只讀 localhost 的資產與固定假行情；沒有網路交易所、真實交易或錢包。50,000 根 SUI-SIM／1m，同 MA20、EMA21、BOLL20/2、VOL、RSI14，初始約160根可見。每版本三組，順序為改後→改前→舊版；沒有隨機化或 CPU/GC 隔離。

Pan 與 zoom 各180次公開 API 操作、每個 rAF 一次（有4秒上限；這九組全部完成180次）。Live 以20ms timer為目標送資料4秒，報告實際 callback 次數，沒有把目標50Hz當作達成。Pan/zoom不是合成手指輸入；真實滾輪、拖動與鍵盤另行人工操作。

`loadMs` 是 navigation 到 workspace ready、再過兩個 rAF 的代理值，包含假資料生成、module載入與UI初始化；不是網路冷載入、正式LCP或所有背景指標完成保證。舊版於ready後逐一加指標，新版於constructor設定，不能把這個差異當作純繪圖引擎速度。
`constructReadyMs` 則未等最後兩個rAF。rAF間隔受螢幕／瀏覽器排程影響；自研CPU欄來自前一個flush的既有lastFrameMs，適合改前／改後比較，舊版沒有同義值。

舊版導航呼叫setBarSpace及scrollToDataIndex，新版呼叫setViewport；API耗時不是等量的純renderer基準。三版原生工具列與pane高度不同，容器相同不代表raster面積相同。實讀pan終點舊版from/to為49767/49927（約160根），自研49766.8705/49925.8705（含分數位移）；zoom約210根，並非偷偷讓新版少畫歷史。

結果支持「本輪降低自研繪製CPU成本」，不支持「每項操作都顯著更快」：
- Pan／zoom／live flush P95中位數約減少56%、67%、68%；這不是整體FPS增幅。
- 自研live幀間隔8.3→8.9ms沒有改善；兩者皆沒有>25ms的live間隔，且改後三組6.3–9.2ms與改前7.6–8.6ms有重疊，不以0.6ms差異下結論或再加複雜機制。
- 載入代理值改善，但constructReady中位數略增6.1ms、樣本波動很大。尚不能保證冷啟動一定更快。
- 舊版在此50k負載較慢，仍是整個版本／公開API流程的差異；不能推廣至所有圖形、裝置或TradingView。

## 記憶體：有修正，但不冒稱完整heap證明

Canvas數字為各canvas.width×height×4總和，不含GPU額外緩衝、DOM、圖像快取及瀏覽器內部配置。改前每層1074×538共3層；改後工具列更精簡、畫布更高（1074×602），仍只配置plot/cursor兩層＋1×1 drawing。

同一個改後版本、相同602px畫布，最後修正前7,758,576→修正後5,172,388 bytes，空繪圖情境減少約33.3%。這個同面積對照比拿不同原生UI比較更適合歸因。

非bench全高畫面人工實讀：空drawing 6,547,108 bytes，拖放趨勢線後9,820,656 bytes；Undo後釋放drawing層。中途下載使UI實體面板變窄，該尺寸下畫線／Undo亦從3,676,200→2,450,804 bytes，沒有混入固定尺寸效能表。

`performance.memory.usedJSHeapSize` 未強制GC、可能共享renderer，起點也不同；只能記錄，不能計為本圖表retained heap或宣稱沒有leak：

## 載入體積與代價

本機量測實際傳送、未壓縮資產（HTTP200、沒有Content-Encoding，不含harness／HTML）：
- 自研改前JS：209,198 bytes。
- 自研改後JS：228,257 bytes，增加19,059 bytes／9.11%，包含本輪樣式與互動功能。
- 舊版engine JS 205,462＋Pro JS568,398＋CSS57,101＝830,961 bytes。

這不是npm壓縮包或正式code-split網路下載量。新版比自身改前變大是本輪明確取捨，沒有拿新UI冒稱免費；更小的無bundler engine entry列在盤點待辦。

## 人工功能觀察與檢查

- 真實滾輪放大後，K棒寬度按間距增加，沒有舊6px half-width cap；實讀最小range9902.099..9921.099（20根）。
- 連續鍵盤縮小到8800..9999（1200根），沒有無限制縮到整段歷史。
- 真實drag放手後第一次讀到8592.252..9791.252，之後無新輸入繼續到8502.613..9701.613，確認有慣性位移；之後回到最新可用。
- 首次趨勢線拖放、線與選取點顯示、Undo清空與Canvas恢復/釋放均實際觀察。
- PNG下載成功，檢視實際PNG有K線、三pane及已提交趨勢線，沒有因drawing層改成1×1而漏圖。
- Chart設定面板實際展開；既有驗證仍由圖表API執行，沒有新增文案、外觀快照或CI測試。

前期iframe量測曾受約1FPS節流；那些設置失敗樣本沒有混入上述top-level結果。本機Brave啟動逾時，沒有修改瀏覽器安全設定；改用同一IAB的獨立top-level頁完成。不是跨瀏覽器／實體觸控裝置／React Native或長時間heap驗收。
