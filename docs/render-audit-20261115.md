# Rendering and calculation audit — 2026-11-15

Scope: owned core and Canvas renderer in this standalone repository. The starting revision was `5b9b7d0b329cd0853735f2eaeb75c70e31baf7f9`. This is an evidence inventory, **not a claim that fifteen optimizations have shipped**. Five areas were changed locally; ten remain candidates requiring workload measurements. No test cases, assertions, fixtures, dependencies or CI workflows were added. No publication is implied.

The related browser comparison measures total interaction separately. The CPU figures below cover geometry construction only; they are not FPS or input-latency promises.

| Area / status | Detail A | Detail B |
| --- | --- | --- |
| 1. Visible pane geometry — changed | `packages/core/src/model/frame.ts` previously sent every pane through generic category-key discovery (`Set`/`Map`, repeated string identities), although normalized snapshots already provide sorted unique category slots. The aligned path now discovers timestamp indexes once per frame. | Geometry now uses the final fractional X and price-scale Y directly. Lower panes no longer construct OHLC rectangles that are immediately discarded. Invalid/unordered/duplicate external candles retain the generic path. |
| 2. Zoomed candle width — changed | Both painters previously capped half-width at 6 logical pixels: even an 85px slot drew a 12px body. The shared `geometry.ts` helper now keeps body width at 68% of the available slot, retaining the existing minimum. | `canvasRenderer.ts` and `seriesRenderer.ts` share the same result for regular/hollow candles, OHLC ticks, columns and histograms. Pure line/area frames without histogram figures do not scan widths. No price, amount or bar count changes. |
| 3. Cursor indicator lookup — changed | `canvasRenderer.ts` previously searched every visible indicator point with `find` on each cursor paint. The ordered point indexes now use binary search. | The final equality check still returns an unavailable value at warmup/null gaps; it never substitutes a nearby indicator reading. |
| 4. Automatic display precision — changed | `buildEngineFrame` derives precision once from the visible snapshot and supplies it to all pane and cursor paints, avoiding repeated OHLC scans on mouse movement. | Explicit `render.pricePrecision` still wins. Manually supplied render frames without the optional derived field retain the original fallback. Prices and indicator values are not rounded in the model. |
| 5. Extended price-series projections — changed | Hollow/outline candles reuse final `bodyTop/bodyBottom` instead of projecting open/close again in both wick and body passes; doji centering and reversed scales retain their existing geometry. | Columns use their slot index only after checking the exact timestamp, with binary-search fallback for nonaligned frames. High-low draws directly from candle values instead of allocating two intermediate arrays. |
| 6. Dense-history painting — pending | `canvasRenderer.ts` still traverses each sampled candle when many more candles than screen pixels are visible. Clipping avoids out-of-bounds pixels, not path construction cost. | A future pixel-column envelope must preserve high/low extrema and expose honest inspection semantics. Silently dropping bars or changing OHLC values is unacceptable; no aggregation was added here. |
| 7. Line/area path reuse — pending | `closePath` rebuilds an area path and a separate line path over the same visible candles. Y projection repeats when both fills and outlines are drawn. | A frame-local cached path could help repeated repaints, but invalidation must include scale, DPR and chart type. Measure actual path-building time before retaining additional objects. |
| 8. Volume-weighted rendering — pending | `seriesRenderer.ts` volume-bars converts candles to `Bar[]` and allocates an intensity array before painting. | Each volume bar uses a distinct alpha and stroke. Quantizing opacity would change the visual encoding; batching must retain the exact intensity or be an explicit approximation option. |
| 9. Optional indicator live updates — pending | `model/indicatorPack.ts` explicitly recalculates optional SC kernels for data changes; `model/classicIndicators.ts` definitions also use full-series calculations. Built-in MA/EMA/RSI/BOLL/MACD/VOL already have incremental paths and must not be counted as missing. | Add per-kernel tail state only where seeds, warmup, correction/prepend behavior and null-gap semantics can be preserved. A single live tick with many optional indicators is a separate workload from viewport pan/zoom. |
| 10. Duplicate indicator instances — pending | `EngineIndicators.compute` calculates each visible instance independently, even if a user adds the same built-in with identical parameters in two panes. | Sharing rows would interact with in-place tail updates and instance removal. A safe cache needs calculation ownership and revision keys; custom definitions cannot be assumed interchangeable merely because their names match. |
| 11. Indicator input allocation — pending | Optional/classic kernels repeatedly build close/high/low arrays via `priceSeries`, `field`, `prices` and intermediate combinations. Multi-indicator initialization can therefore spend time preparing the same fields. | A calculation-scoped shared field view could reduce allocations without retaining another full history indefinitely. Do not memoize solely by array identity because real-time arrays are updated in place. |
| 12. Cursor inspection fan-out — pending | Each pane calls `frame.inspect`, which locates the selected bar and copies all indicator rows; the host can then request the top-level inspection again. Binary point lookup in area 3 does not remove this work. | A future lightweight paint inspection and one public inspection per selected index could help. Reusing externally exposed mutable objects or returning a previous bar during data updates would be incorrect. |
| 13. Axis formatting — pending | Date-time formatter construction is already bounded and cached. Calendar parts and crosshair text are nevertheless formatted repeatedly; `calendarDate` creates temporary filter/map arrays. | Label caches should be scoped to the frame and include timezone, timespan, symbol timezone and formatter callbacks. Avoid caching arbitrary host formatting callbacks by price alone. This small candidate is lower priority than geometry. |
| 14. Drawing geometry workload — pending | `chart.ts` reprojects drawings when the viewport changes; `drawingGeometry.ts` samples some curves with fixed 64/96 segments, while arcs use a bounded screen-size rule. Large drawing collections need a separate measurement. | Viewport-aware bounds rejection and adaptive curve subdivision may help, but rays, channels and anchored VWAP can intersect the viewport while their anchors are offscreen. Anchor-only culling would lose valid drawings. |
| 15. Main-thread scheduling / worker feasibility — pending | Canvas painting and frame construction run on the main thread. The existing separate cursor/drawing layers and dirty flags already prevent some redundant repainting; this audit does not claim they are missing. | Worker/OffscreenCanvas work must include transfer costs, custom indicator callbacks, font/image handling, hit testing and browser fallback. No WASM/worker dependency was introduced without demonstrating an actual remaining bottleneck. |

## Preserved correctness boundaries

- No OHLC aggregation, decimation, indicator formula, time-ordering or precision-rounding change.
- The optimized frame still preserves bordering candles for continuous lines, exact fractional projection, per-pane price scales, indicator bases, warmup gaps and logarithmic/reversed/percentage behavior.
- Generic malformed external snapshots use the previous financial-model route. This does not introduce a new promise to accept arbitrary invalid viewport inputs.
- The supplied render frame is treated as a snapshot. Hosts that manually mutate its OHLC data must construct a fresh frame or omit its optional derived precision.
- Cursor layers remain separate; no additional pipeline or blanket suite execution was introduced.

See [render measurements](render-measurements-20261115.md) for actual observations and limitations. Remaining areas above are investigation candidates, not completed features or required new gates.
